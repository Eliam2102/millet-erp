## Cambio construido

El receptor se valida antes de reservar folio y antes del adaptador PAC que sustituye identidades en sandbox. `ValidadorReceptorFiscal` consulta `IClientesReadPort.ObtenerAsync` cuando el cliente se conoce y aplica una regla pura al snapshot que va a timbrarse. Venta recibe `ClienteId` opcional; si hay pedido, se usa su cliente como respaldo y se rechaza un ID explícito distinto al del pedido.

La regla `ValidacionReceptorFiscal` agrupa RFC, razón social, régimen, CP y uso; conserva también la restricción existente del país obligatorio de hasta cinco caracteres. `CompatibilidadUsoRegimen` contiene la matriz inmutable de D1 suministrada en el encargo; no requiere migración. Se verifica también existencia de régimen y uso en los catálogos vigentes. La comparación con el maestro ignora espacios y mayúsculas; el snapshot debe satisfacer el formato fiscal. Se rechazan todos los faltantes juntos.

- XAXX: 616, S01 y CP del lugar de expedición.
- XEXX: 616, S01, CP del lugar de expedición y país extranjero; en exportación CCE se exigen NumRegIdTrib y país de residencia.
- REP: CP01 es el uso efectivo, también para genéricos; prevalece la instrucción de D2 para comprobantes de pago.
- Cobertura: venta, anticipo, NC de bonificación y ranura, amortización con el mismo receptor ya validado de la factura, REP, reintento y emisión diferida por pedimento. Carta porte conserva su comportamiento.

`ReceptorFiscalInvalidoException` deriva de `BusinessRuleException`; se abrió esta clase base para permitir la excepción específica con metadatos. El `GlobalExceptionHandler` responde 422 con `code`, `campos`, `clienteId` y `enlaceCliente`. Las reglas fiscales de receptor que antes cortaban con un 400 de FluentValidation se concentran en esta respuesta agregada; las demás validaciones de comando siguen en FluentValidation.

El frontend envía el ID y reutiliza `ReceptorIncompletoBanner`, con componentes de UI y tokens, para mostrar el diagnóstico del servidor y el enlace. El parser es una función pura con validación Zod y `zId()`. La corrección fiscal se hace en el maestro; el aviso no otorga permisos adicionales. También se conserva el país seleccionado del cliente extranjero cuando la venta no lleva CCE.

Las fixtures de pruebas anteriores se actualizan con un maestro fiscal explícito y, para RFC genéricos, CP igual al del emisor. No se relajó el validador para acomodar fixtures inválidas.
